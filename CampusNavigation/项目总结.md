# 校园导航系统 - 课程设计总结报告

## 一、项目介绍与设计目的

### 1. 项目介绍

#### 1) 项目名称
校园导航系统（CampusNavigation）

#### 2) 项目设计背景
传统校园导航方式依赖于纸质地图或口头指路，存在易过时、不便携、查询低效等问题。本项目面向高校师生的日常校园出行需求，采用C++开发轻量级跨平台的数字导航系统，以本地文件存储地点和道路数据，应用图论与最短路径算法，解决传统导航痛点，实现校园地理信息的高效查询与路径规划。

**主要功能模块：**
- **基础支撑模块**：负责数据存储解析（地点文件加载/保存、道路信息加载/保存）、地点ID与索引的映射管理、输入校验与内存管理，保障系统稳定运行；
- **核心业务模块**：涵盖地点操作（添加/删除/修改地点，含ID唯一性校验）、查询功能（按ID精确查找、按名称模糊查询并展示详情）、道路管理（建立地点间的连接关系和距离信息）、最短路径计算（基于Dijkstra算法规划最优路线）、可视化展示（表格化呈现地点信息和道路拓扑），搭配菜单交互模块实现用户操作闭环。

### 2. 设计目的

**本系统的设计核心是用数字化方式解决传统纸质地图和口头指路的不足，通过模块化功能实现校园地点信息和路径规划的全面管理，具体体现在：**

**1) 功能实现**
- 搭建了数据存储（本地文件加载/保存）、地点管理（添加、删除、修改、查询）、道路管理（建立和维护地点连接）、路径规划（计算最短路径）、可视化展示（表格化呈现地点和道路信息）的完整功能体系，同时通过输入校验保证数据规范和一致性。

**2) 设计意义**
- 为高校提供轻量级、零部署成本的校园导航解决方案，解决纸质地图更新慢、难以修改、查询低效的问题；
- 系统架构预留扩展空间（如支持多条路线对比、动态权重调整等），兼顾实用性与可迭代性；
- 优化用户操作体验，通过友好的菜单界面和模糊查询功能，降低导航工具的使用门槛，提升师生的校园出行效率。

### 3. 核心知识点应用
- **图论与邻接表**：采用邻接表（vector<vector<pair<int,int>>>）实现校园导航图，高效存储地点间的拓扑关系和距离权重；
- **最短路径算法**：通过Dijkstra算法配合优先队列实现单源最短路径计算，时间复杂度O((V+E)logV)，保证路径规划的最优性；
- **动态数据结构**：利用向量（vector）和哈希表（unordered_map）实现地点的动态增删改查，支持ID到索引的O(1)映射；
- **文件I/O与持久化**：通过ifstream和ofstream完成地点和道路数据的文件读写，实现数据的永久存储与恢复；
- **面向对象设计**：采用PlaceManager和Graph两个类分离地点管理和图管理职责，提高代码的可维护性和可扩展性；
- **输入校验与异常处理**：实现ID唯一性检验、文件异常捕获等机制，保障数据的完整性和系统的稳定性。

### 4. 课程设计意义
- **知识融合应用**：将链表、图论、树形结构等离散的数据结构知识点与实际的校园导航场景相结合，实现"数据结构适配业务"的核心思维；
- **工程化能力培养**：锻炼模块化编程、异常处理、内存管理等工程实践能力，积累从需求分析到系统设计、代码实现、测试验证的全流程开发经验；
- **算法实践体验**：通过Dijkstra算法的实现和应用，深化对贪心算法和图算法的理解，建立理论知识与实际问题求解的连接；
- **问题分析与优化**：在地点/道路管理和路径查询的不同场景下，选择合适的数据结构和算法，培养权衡时间空间复杂度、面向业务优化的工程思维，为后续复杂系统开发奠定坚实基础。

| 项目 | 要求 | 说明 |

| **操作系统** | Windows 10+ / Linux / macOS | 项目采用跨平台C++开发，通过条件编译支持多平台 |

- **标准C++库**（STL）：
  - `<vector>` - 动态数组，存储地点和邻接表

  - `<string>` - 字符串处理

  - `<queue>` - 优先队列，实现Dijkstra算法

  - `<direct.h>` / `<sys/stat.h>` - Windows/Unix平台的目录创建操作

## 四、项目需求分析

本校园导航系统旨在为高校师生提供便捷的校园地点查询和路径规划服务，解决传统纸质地图更新困难、路径规划不便的问题。系统需求主要分为功能性需求和非功能性需求两大类。

### 1. 功能性需求

功能性需求是系统需求的核心部分，根据用户操作场景和业务模块划分，主要包括地点管理、道路管理、路径查询、数据持久化等功能模块。

#### 1.1 地点信息管理功能

**功能描述**：系统需要支持校园地点信息的全生命周期管理，包括地点的添加、删除、修改和查询操作。

**具体需求**：
- **添加地点**：用户输入地点ID和名称，系统需验证ID的唯一性，防止重复添加；添加成功后自动保存至数据文件。
- **删除地点**：用户指定地点ID，系统需删除该地点及其相关的所有道路连接，同时更新图的顶点数量，确保数据一致性。
- **修改地点**：用户指定地点ID和新名称，系统需查找该地点并更新其名称信息，修改后保存至文件。
- **查询地点**：支持两种查询方式：按ID精确查找（返回唯一结果），按名称模糊查找（返回所有匹配结果），满足不同查询场景需求。
- **显示所有地点**：以表格形式展示所有已录入的地点ID和名称，便于用户浏览和管理。

#### 1.2 道路信息管理功能

**功能描述**：系统需要支持校园道路（地点间连接）的管理，包括道路的添加和查看功能。

**具体需求**：
- **添加道路**：用户输入起点ID、终点ID和距离（权重），系统需验证两个地点是否存在，建立双向连接关系（无向图），并保存至道路数据文件。
- **查看道路**：以邻接表形式展示所有道路信息，每个地点后列出其相邻地点及对应距离，便于用户了解校园拓扑结构。

#### 1.3 最短路径查询功能

**功能描述**：系统需要基于Dijkstra算法计算任意两地点间的最短路径，为用户提供最优出行方案。

**具体需求**：
- **路径计算**：用户输入起点ID和终点ID，系统使用Dijkstra算法计算最短路径，返回完整的路径序列（途经地点列表）和总距离。
- **路径展示**：以易读格式展示计算结果，如"起点 → 中转点1 → 中转点2 → 终点，总距离：XXX米"，便于用户理解和使用。
- **异常处理**：若起点或终点不存在，或两点间无可达路径，系统需给出明确提示信息。

#### 1.4 数据持久化功能

**功能描述**：系统需要支持地点和道路数据的文件存储，实现数据的永久保存和跨会话使用。

**具体需求**：
- **数据加载**：程序启动时自动从places.txt和roads.txt加载地点和道路数据，构建内存中的数据结构。
- **数据保存**：用户执行添加、删除、修改操作后，系统需自动将变更同步至数据文件，确保数据不丢失。
- **文件格式**：采用简洁的文本格式存储（地点文件：ID 名称；道路文件：起点ID 终点ID 距离），便于数据导入导出和人工编辑。

#### 1.5 交互菜单功能

**功能描述**：系统需要提供清晰友好的菜单界面，引导用户完成各项操作。

**具体需求**：
- **菜单显示**：以数字选项形式展示所有可用功能（1-7号功能 + 0退出），简洁明了。
- **输入响应**：用户输入选项编号，系统调用对应功能模块并处理用户输入的参数。
- **循环交互**：操作完成后自动返回主菜单，支持连续操作，直至用户主动退出。
- **输入校验**：对用户输入的ID、距离等参数进行合法性校验，防止非法输入导致系统异常。

### 2. 非功能性需求

非功能性需求主要描述系统在性能、易用性、安全性、可维护性等方面的质量属性要求。

#### 2.1 性能要求

- **响应速度**：对于百级地点规模的校园（100个地点、1000条道路），最短路径计算应在1秒内完成，确保用户体验流畅。
- **内存占用**：系统运行时内存占用应控制在50MB以内（邻接表存储 + STL容器），适配普通配置计算机。
- **文件I/O效率**：地点和道路数据的加载/保存操作应在500毫秒内完成，避免用户等待时间过长。
- **算法复杂度**：Dijkstra算法时间复杂度为O((V+E)logV)，空间复杂度为O(V)，满足校园规模应用需求。

#### 2.2 易用性要求

- **界面友好**：采用清晰的中文菜单和提示信息，功能选项采用数字编号，降低操作门槛。
- **操作简便**：用户无需了解图论算法和数据结构知识，按照提示输入参数即可完成操作。
- **查询灵活**：支持按ID精确查找和按名称模糊查询两种方式，适配不同用户习惯和使用场景。
- **信息清晰**：地点展示、道路展示、路径结果等信息以表格或列表形式呈现，层次分明，易于理解。
- **错误提示**：当用户输入非法参数或执行失败操作时，系统给出明确的错误提示和解决建议。

#### 2.3 数据安全性要求

- **数据一致性**：删除地点时自动清理相关道路，修改操作即时保存，确保内存数据与文件数据一致。
- **输入校验**：对ID唯一性、地点存在性、距离非负性等进行严格校验，防止非法数据破坏系统。
- **文件保护**：采用文件锁机制（如C++的ofstream独占模式），防止多进程同时写入导致数据损坏。
- **异常处理**：文件打开失败、内存分配失败等异常情况需捕获并给出提示，避免程序崩溃。

#### 2.4 可维护性要求

- **代码结构清晰**：采用面向对象设计，PlaceManager和Graph类职责分离，main.cpp仅负责交互流程。
- **模块化设计**：地点管理、图管理、文件工具独立封装，便于单元测试和功能扩展。
- **注释完整**：关键函数、算法实现处添加注释说明，便于代码阅读和后期维护。
- **可扩展性**：预留功能扩展接口，如支持有向图、多条路线对比、A*算法等，便于后续升级。

#### 2.5 兼容性要求

- **跨平台支持**：通过条件编译（#ifdef _WIN32）支持Windows、Linux、macOS三大主流操作系统。

```cpp
struct Place {
```

```cpp
private:
```


### 2. 数据元素之间的关系

#### 2.1 地点与地点的关系

地点与地点之间通过道路（边）相连，形成一个无向加权图：
- **一对多关系**：一个地点可以与多个其他地点通过道路相连（相邻地点）。
- **对称性关系**：若地点A与地点B有道路相连，则地点B与地点A也有道路相连（无向图）。
- **权重关系**：每条道路都有一个非负整数权重（距离），用于最短路径计算。

#### 2.2 地点与ID的映射关系

为了支持快速的地点查找，系统维护ID与内存地址的映射关系：
```cpp
std::unordered_map<int, int> idIndex;  // 地点ID → 向量索引的映射
```

**作用**：
- 支持O(1)时间复杂度的ID查找
- 例：findById(3) 通过哈希表直接定位地点3在places向量中的位置，无需遍历

#### 2.3 地点集合与邻接表的关系

PlaceManager维护的地点集合与Graph维护的邻接表需要保持同步：
- **大小一致**：邻接表的顶点数应等于地点总数
- **索引对应**：地点在places向量中的索引等于其在邻接表中的顶点编号
- **同步操作**：添加/删除地点时，需同时调整邻接表的大小

### 3. 选择邻接表存储结构的理由

#### 3.1 邻接表优势分析

**空间复杂度优化**：
- 邻接表空间：O(V + E)，其中V为顶点数（地点数），E为边数（道路数）
- 邻接矩阵空间：O(V²)
- 对于校园导航，地点数量较少（100以内），道路数也相对有限，邻接表能显著节省空间

**时间复杂度权衡**：
- 查询相邻地点：O(degree)，即查询某地点的相邻地点时间与其度数成正比
- 添加/删除边：O(1)~O(degree)，通过vector的push_back可快速添加
- Dijkstra算法配合优先队列：O((V + E)logV)，优于邻接矩阵的O(V²)

**应用场景匹配**：
- 校园导航是稀疏图（地点数<100，道路数通常<1000），邻接表优于邻接矩阵
- 频繁执行Dijkstra算法查询最短路径，邻接表遍历边时效率更高

#### 3.2 与哈希表的组合设计

**哈希表作用**：
- 快速ID查找：O(1)时间内判断地点是否存在
- 防止重复ID：添加地点时检查idIndex，确保ID唯一性
- 支持按ID删除：快速定位待删除地点的位置

**组合优势**：
- PlaceManager用vector存储地点有序集合，哈希表加速查找
- Graph用邻接表存储拓扑结构，支持高效的图遍历和最短路径计算
- 两者结合既保证了数据的有序管理，又提供了快速查询能力

#### 3.3 与动态内存管理的适配

**选择STL容器的理由**：
- vector和unordered_map自动管理内存，避免手动分配释放导致的内存泄漏
- 支持动态扩容，适应地点和道路数量的增加
- 提供丰富的接口（push_back、erase、find等），简化代码实现

- 核心数据结构为`vector<vector<pair<int,int>>> adj`，其中adj[u]存储与顶点u相邻的所有顶点及距离

**2) 道路的添加与管理**

路径规划模块实现最短路径计算核心算法，为用户提供最优出行方案。

**1) Dijkstra算法实现**

**2) 路径构造与回溯**

**3) 结果展示**
- 将路径序列通过"地点ID → 地点ID → ... → 地点ID"格式展示，同时给出总距离
- 若无可达路径则输出"无法到达"提示

本系统按照模块化设计思想，分模块逐一实现各功能。以下详细介绍各模块的实现思想、关键代码及测试过程。

### 1. 地点管理模块（PlaceManager）

#### 1) 实现思想

地点管理模块的核心思想是采用**向量+哈希表**的组合数据结构，既保证地点的有序存储，又支持快速的ID查找。具体实现要点：

- **数据存储策略**：使用`vector<Place>`存储地点集合，保证地点按添加顺序排列；使用`unordered_map<int, int>`维护地点ID到向量索引的映射，实现O(1)的快速查找。
- **增删改操作设计**：添加操作先检查ID唯一性，再插入向量尾部并更新哈希表；删除操作采用**交换删除法**，将待删除元素与最后一个元素交换后pop_back()，避免大规模元素移动；修改操作通过哈希表定位后直接更新。
- **持久化机制**：每次修改操作后立即调用`saveToFile()`，采用覆盖写入方式将完整的places向量同步至文件，确保数据不丢失。
- **查询功能设计**：按ID查找通过哈希表O(1)定位；按名称查找遍历向量进行字符串匹配（支持子串查找），返回所有匹配结果的指针数组。

#### 2) 关键代码

**数据结构定义**：
```cpp
class PlaceManager {
private:
    std::vector<Place> places;                      // 地点集合
    std::unordered_map<int, int> idIndex;          // ID到索引的映射
    std::string filename;                           // 数据文件路径

public:
    // 文件加载 - 构建内存数据结构
    bool loadFromFile() {
        ifstream in(filename);
        if (!in.is_open()) {
            cout << "ERROR: 无法打开文件：" << filename << endl;
            return false;
        }

        places.clear();
        idIndex.clear();

        Place p;
        while (in >> p.id >> p.name) {
            if (idIndex.count(p.id)) {
                cout << "WRONG: 地点编号重复：" << p.id << endl;
                continue;
            }
            idIndex[p.id] = places.size();
            places.push_back(p);
        }

        in.close();
        return true;
    }

    // 添加地点 - ID唯一性校验
    bool addPlace(int id, const std::string &name) {
        if (idIndex.count(id)) {
            cout << "【错误】地点编号已存在：" << id << endl;
            return false;
        }

        Place p{ id, name };
        idIndex[id] = places.size();
        places.push_back(p);
        this->saveToFile();
        return true;
    }

    // 删除地点 - 交换删除法优化
    bool deletePlace(int id) {
        if (!idIndex.count(id)) {
            cout << "【错误】地点不存在：" << id << endl;
            return false;
        }

        int idx = idIndex[id];              // 获取待删除元素索引
        int lastIdx = places.size() - 1;     // 获取最后一个元素索引

        // 将最后一个元素移动到删除位置
        places[idx] = places[lastIdx];
        idIndex[places[idx].id] = idx;       // 更新移动元素的索引

        // 删除最后一个元素
        places.pop_back();
        idIndex.erase(id);

        this->saveToFile();
        return true;
    }

    // 按ID查找 - O(1)哈希查找
    Place* findById(int id) {
        if (!idIndex.count(id)) return nullptr;
        return &places[idIndex[id]];
    }

    // 按名称模糊查找 - 支持子串匹配
    vector<Place*> findByName(const string& keyword) {
        vector<Place*> result;
        for (auto& p : places) {
            if (p.name.find(keyword) != string::npos) {
                result.push_back(&p);
            }
        }   
        return result;
    }
};
```

**测试要点**：
- ID唯一性校验：尝试添加重复ID，系统正确拒绝
- 删除操作正确性：删除中间元素后，向量保持紧凑，哈希表同步更新
- 查询功能：按ID查找不存在地点返回nullptr，按名称模糊查找"图书"能匹配"图书馆"、"图书室"

### 2. 图/道路管理模块（Graph）

#### 1) 实现思想

图管理模块采用**邻接表**存储无向加权图，设计要点如下：

- **邻接表结构**：使用`vector<vector<pair<int,int>>> adj`表示，其中adj[u]存储与顶点u相邻的所有顶点及距离。pair的first为终点ID，second为距离权重。
- **无向图处理**：添加边(u,v,w)时，同时向adj[u]和adj[v]添加对应的pair，实现双向连接。
- **动态调整顶点数**：`resizeTo(newN)`方法在地点增删时调整邻接表大小。缩小时需清理超出范围的边（遍历邻接表，删除终点ID>newN的边）。
- **文件持久化**：保存时遍历邻接表，为避免无向边重复保存，仅输出u<v的边；加载时读取文件并调用addEdge()重建邻接表。

#### 2) 关键代码

**邻接表核心实现**：
```cpp
class Graph {
private:
    int n;  // 顶点数量
    std::string filename;
    std::vector<std::vector<std::pair<int, int>>> adj;  // 邻接表

public:
    Graph(int n = 0, const std::string& file = "") : n(n), filename(file) {
        adj.resize(n + 1);  // 顶点编号从1开始
    }

    // 添加无向边
    void addEdge(int u, int v, int w, bool needToSave) {
        adj[u].push_back({v, w});
        adj[v].push_back({u, w});  // 无向图双向添加
        
        if (needToSave) {
            this->saveToFile();
        }
    }

    // 动态调整顶点数
    void resizeTo(int newN) {
        if (newN <= 0 || newN == n) return;

        // 如果缩小，需要清理越界的边
        if (newN < n) {
            for (int u = 1; u <= newN; ++u) {
                auto &edges = adj[u];
                edges.erase(std::remove_if(edges.begin(), edges.end(), 
                    [newN](const std::pair<int,int>& e) {
                        return e.first > newN;
                    }), edges.end());
            }
            this->saveToFile();
        }

        n = newN;
        adj.resize(n + 1);
    }

    // 保存邻接表至文件（避免重复保存无向边）
    bool saveToFile() const {
        ofstream out(filename);
        if (!out.is_open()) {
            cout << "【错误】无法写入文件：" << filename << endl;
            return false;
        }

        for (int u = 1; u <= n; u++) {
            for (auto i : adj[u]) {
                int v = i.first, w = i.second;
                if (u < v)  // 仅保存u<v的边，避免重复
                    out << u << " " << v << " " << w << endl;
            }
        }

        out.close();
        return true;
    }

    // 打印图的拓扑结构
    void printGraph() const {
        for (int u = 1; u <= n; ++u) {
            cout << "地点 " << u << ": ";
            for (auto i : adj[u]) {
                int v = i.first, w = i.second;
                cout << "(" << v << ", " << w << ") ";
            }
            cout << endl;
        }
    }
};
```

**测试要点**：
- 无向边验证：添加边(1,2,100)后，adj[1]和adj[2]均包含对应的pair
- 动态调整：删除地点5后，所有包含顶点5的边被清理
- 文件保存：roads.txt中每条无向边仅保存一次

### 3. 路径规划模块（Dijkstra算法）

#### 1) 实现思想

路径规划模块基于**Dijkstra算法**实现单源最短路径计算，并采用**优先队列优化**以提升性能：

- **算法核心**：维护dist[]数组记录起点到各顶点的最短距离，vis[]数组标记已处理顶点，prev[]数组记录路径前驱，用于回溯路径。
- **优先队列优化**：使用`priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>>`维护待处理顶点，每次取出距离最小的顶点进行松弛操作，时间复杂度从O(V²)优化至O((V+E)logV)。
- **路径回溯**：通过prev[]数组从终点反向追溯至起点，存入vector后reverse()得到正向路径。
- **异常处理**：若终点距离仍为INT_MAX，说明两点不连通，返回空路径和-1距离。

#### 2) 关键代码

**Dijkstra算法完整实现**：
```cpp
pair<int, vector<int>> Graph::dijkstra(int start, int end) const {
    vector<int> dist(n + 1, INT_MAX);         // 距离数组，初始化为无穷大
    vector<bool> vis(n + 1, false);           // 访问标记数组
    vector<int> prev(n + 1, -1);              // 前驱节点数组

    // 优先队列：pair<距离, 顶点>，按距离从小到大排序
    priority_queue<pair<int, int>, vector<pair<int, int>>, greater<pair<int, int>>> pq;

    dist[start] = 0;
    pq.push({0, start});

    while (!pq.empty()) {
        auto tt = pq.top();
        int u = tt.second;
        pq.pop();

        // 跳过已访问顶点（优先队列中可能有重复元素）
        if (vis[u]) continue;
        vis[u] = true;

        // 提前终止优化：找到终点即可返回
        if (u == end) break;

        // 松弛操作：更新相邻顶点的最短距离
        for (auto i : adj[u]) {
            int v = i.first, w = i.second;
            
            // 防止整数溢出 + 距离更新判断
            if (dist[u] != INT_MAX && dist[v] > dist[u] + w) {
                dist[v] = dist[u] + w;
                prev[v] = u;
                pq.push({dist[v], v});
            }
        }
    }

    // 路径回溯：从终点追溯到起点
    vector<int> path;
    if (dist[end] != INT_MAX) {
        for (int cur = end; cur != -1; cur = prev[cur]) {
            path.push_back(cur);
        }
        std::reverse(path.begin(), path.end());
    }

    return {dist[end], path};
}
```
